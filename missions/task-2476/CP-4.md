# CP-4 — Real replay closure

Ran the real isolated demo on the final tree, inspected the raw cast and the rendered GIF, and repaired every in-scope defect the replay exposed. The prior checkpoints (CP-1 inventory, CP-2 execution story, CP-3 verification/handoff story) changed the implementation but never exercised it through a real configured-agent run, so several defects survived their focused tests. This checkpoint closes that gap.

Before recording, the focused tests passed while the real output still violated the operator story. The replay exposed four defects, three of them real SC4/SC7 violations and one a regression introduced while fixing the third:

1. The `active` command still led with the full workspace preflight dump (PWD, branch, Backlog status, Mission doc, last commit, `USABLE` verdict). Those are routine-PWD/backlog diagnostics, not the operator story (SC7).
2. The `active` path still emitted the Backlog task-sync line `Task … transitioned to active (assignee=…) and committed.` (SC7 task-synchronization).
3. Handoff verdicts printed as nested prefixes (`[INFO] [PASS] Repository verification passed.`, `[INFO] [PASS] Implementation is ready for independent review.`) because `fmt.log.info` prepended `[INFO]` to already status-tagged lines (SC4).
4. Fixing #3 with `fmt.stripAnsi` inside `cli-format.ts` crashed with `fmt is not defined` — `fmt` is not a self-reference in that module. Corrected to the module-local `stripAnsi`.

The demo also exercised a real selected-to-fallback reviewer change (`claude` credentials needed refresh → `codex` → `custom`) and a `codex` launch failure; both stayed loud instead of being log-level-hidden, as required (SC5).
