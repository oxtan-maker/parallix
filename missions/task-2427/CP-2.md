# CP 2 — Trusted composition adapter + availability + TUI gating

## Summary of work done

`src/composition/production-capabilities.ts`: `composeProductionCapabilities` now supplies the shared `BoardCommandController` (and, via the same `BoardMissionServices` object, the `board-projection.ts` `commandControllerFactory` controller) a `draft` service built by the new `createBoardDraftService` — the application-owned `DraftCommandUseCase` over `createDraftWorkflowAdapter` from `src/adapters/cli/commands/draft.js`, with a **throwing `exitFn`**, **progress-sink `logFn`/`errorFn`** (events on the composition `BoardProgressSink`, `draft-log`/`draft-error` phases; no console output), the **composition-owned `missionServicesFn`** (the same `MissionIntakeService` instance and canonical `owningRepositoryId` the controller already uses — no second database open), and the composition `currentWork` port. The review repair also routes `ensureWorktree` and agent-config reads through that throwing board boundary, including the post-process restart path, so those legacy CLI helpers cannot terminate the board host. The service exists **only when Mission authority is available** (null store ⇒ no `draft` slot ⇒ typed unavailable, read-only graph unchanged). A `ProductionCompositionOverrides.draftWorkflow` seam lets test graphs inject a mocked `DraftWorkflowPort` so no real git/agent/SQLite-in-workflow path runs in unit tests.

`src/application/projections/mission-board.ts`: `BoardCommand` gained `'draft'`; `availableBoardCommands` reports a `draft` entry enabled only for `open && mission.status === 'backlog'` (the pre-draft state), with a reason string naming the constraint. `src/interfaces/tui/action-bar.tsx`: `canDispatchAction('draft:create', …)` gates on `commandController.canExecute('draft:create')` ∩ the card's `draft` availability (the TASK-2426 instance-query pattern), and the disabled-row reason renders the projection's eligibility text.

Tests: `test/task-2426-repro.test.ts` extended with wired draft coverage (dispatch reaches the injected mocked workflow once per step; the TUI factory controller exposes the same wiring; a default-construction test proves the real trusted adapter path builds), read-only coverage (no draft service ⇒ `canExecute` false, dispatch returns the typed `capability` rejection with no store access), and `draft:create` removed from the unavailable-kinds matrix. `test/tui-action-bar.test.ts` updated to the new gating matrix; `test/tui-command-flow.test.ts` updated: Ctrl+D unwired ⇒ typed unavailable (no dispatch), Ctrl+D wired + backlog card ⇒ confirmation ⇒ one `draft:create` dispatch, Ctrl+D wired but past-pre-draft card ⇒ no confirmation, no dispatch.
