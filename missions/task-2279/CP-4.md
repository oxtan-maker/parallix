# CP-4: Bundle compatibility and rollback validation

Validated the canonical ESM bundle on Node v22.23.1. The source runner and
bundle both execute `--version` and the read-only `config` command. Tests now
resolve historical `dist/` module spelling to the source runtime through a
test-only alias, so they remain source-level and hermetic while the ignored
CommonJS `dist/` tree stays an explicit rollback shim and is regenerated by
the esbuild production build alongside the canonical ESM artifact. Shipped
prompts and configuration are read through the logical-key `AssetStore`
boundary; the bundle asset manifest records those keys and content digests.
Static analysis now
checks `src/` and never emits production JavaScript.

The migration does not wait for a newer Node: Node 25/26 is an ADR 0044
prerequisite only for TASK-2286's ESM SEA executable. The remaining dist shim
is owned by TASK-2285's npm package compatibility gate and must not be removed
by this mission.
