# CP-16: Drop the review-loop change, make the bootstrap recoverable

## Summary

Acted on round 4. Two changes.

**F1 — the unrelated review-loop repair is gone.** `src/adapters/review/rebase.ts`
and `test/review.test.ts` are restored to the merge-base `ab771ae08` content, so
`git diff main -- src/adapters/review/rebase.ts test/review.test.ts` is empty and
the mission diff no longer touches the pre-review rebase handoff. The reviewer's
analysis is accepted: the `conflictAgentLaunched` flag is redundant, because
`src/application/rebase-workflow.ts` starts the `conflict-resolution` agent only
after a non-empty `sharedFiles` has been established and never clears it
afterwards, and the accompanying test passed against baseline `rebase.ts`, so it
pinned nothing. The cleanup is parked as Backlog task `task-2529`, whose first
acceptance criterion requires a test that fails against the current
`src/adapters/review/rebase.ts` before the flag is removed.

**F2 — `npm run sonar:setup` now recovers from a server-side token orphan.**
`setupSonar()` in `scripts/sonar-local.ts` issues `POST /api/user_tokens/revoke`
for `parallix-local-scanner` before `POST /api/user_tokens/generate`, so the
previously terminal state — SonarQube holding the token while the local file at
`<forgejo home>/tokens/sonarqube` does not — is cleared by the repository-owned
command instead of the SonarQube UI that the mission Goal excludes. A revoke
response that is neither OK nor `404` is reported rather than swallowed, so a
wrong administrator password still fails loudly instead of falling through to a
confusing generate error. Reuse is unaffected: when the local file is present,
`setupSonar()` still returns before any request, so neither call is made.
