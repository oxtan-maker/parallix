## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
At review time `process.env` is read about 107 times across about 50 production files in `src/`. Ambient environment reads spread through adapters and helpers make configuration hard to discover, document, and test (tests must mutate global env instead of passing values), and they bypass the composition root that AGENTS.md names as the configuration authority.

The outcome is a single, discoverable place where Parallix's supported environment variables are read, validated, and turned into typed configuration that is passed inward. Adapters that legitimately pass the environment to child processes (agent launches, git, gates) may keep forwarding an env object, but they do not interpret individual variables themselves.

This touches composition authority. Before implementing, present the inventory of env reads, the proposed ownership, and alternatives to the operator and get an explicit decision, as AGENTS.md requires.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 An inventory of every environment variable Parallix interprets is produced and presented to the operator with a proposed owner before implementation
- [ ] #2 Interpreted environment variables are read and validated in one composition-owned module and passed inward as typed configuration
- [ ] #3 Outside that module, production code reads process.env only to forward an environment to child processes, enforced by a guard test
- [ ] #4 Each supported environment variable is documented in docs/config.md
- [ ] #5 Affected unit tests supply configuration explicitly instead of mutating process.env
