## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Base: TASK-2500. Mission 4 of 6. Create an explicit deterministic test tier safe to run on a clean GitHub-hosted runner WITHOUT: local AI; operator model configuration; Forgejo-specific credentials/state; workstation-specific state; assumptions about existing worktrees; private local services.

This must become a first-class test category, not an exclusion hack.

CURRENT SUITE CLASSES (to classify): hermetic unit tests; process/Git/filesystem integration tests; Forgejo-boundary tests; full mission lifecycle tests; tests requiring real agent/model configuration; local-AI smoke/e2e tests. `npm run test:integration` is therefore NOT automatically suitable as a required GitHub check.

DEPENDENCY ORDER: base TASK-2500. Depends on none. Can start immediately in parallel with Mission 1. Mission 5 (TASK-2500.05) follows this one.
<!-- SECTION:DESCRIPTION:END -->

## Mission Requirements

- Define explicit categories along the lines of: `unit`, `integration-ci`, `integration-local`, `agent-e2e`. Names may differ; semantic separation must be explicit.
- Prefer POSITIVE membership ("these tests ARE CI-safe") over negative filtering ("run everything except tests containing real-agent"). A newly added boundary test must not silently enter the GitHub-safe tier merely because nobody excluded it.
- Audit the current test suite and classify every test family.
- Add stable commands such as: `npm run test:ci`, `npm run test:integration:ci`, `npm run test:integration:local`, `npm run test:agent-e2e`. Naming may vary.
- GitHub-safe verification covers at minimum where practical: build; typecheck; hermetic unit tests; deterministic clean-checkout integration tests; package/bundle validity where portable.
- Tests requiring real local AI remain available and required by the appropriate local Parallix integration policy, but must NOT make GitHub CI depend on the user's model infrastructure.
- Measure runtime and tune obvious pathological cases. Do NOT weaken meaningful coverage to hit an arbitrary runtime target.
- Existing local trust gates are not accidentally weakened.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A documented classification exists for every test family.
- [ ] #2 GitHub-safe tests pass on a clean machine with no local AI/model service.
- [ ] #3 CI-safe test selection is deterministic.
- [ ] #4 Adding a new integration test requires an explicit classification decision.
- [ ] #5 Local real-agent/e2e coverage remains runnable.
- [ ] #6 Existing local trust gates are not accidentally weakened.
- [ ] #7 Runtime of the CI-safe suite is recorded.
<!-- AC:END -->

## Deliverable
Document: what GitHub CI proves / what local Parallix verification proves / what only real-agent/local-AI verification proves. This distinction is part of the trust model, not merely test-runner plumbing.
