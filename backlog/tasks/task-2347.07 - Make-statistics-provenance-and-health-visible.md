## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Telemetry loss and projection failure are indistinguishable from genuine
measurements of zero.

- `recordLaneTransitionSafely`
  (`src/application/recording/board-event-recorder.ts:47`) swallows every
  recording failure and returns `false`, and the production call site wraps the
  whole recording block in a bare `catch {}` with the comment "Recording failure
  is silently swallowed" (`src/adapters/backlog/backlog.ts:824-828`). Nothing
  counts or surfaces the loss.
- `BoardProjectionBuilder.buildMetrics` catches any adapter error and falls
  through to `defaultMetrics` (`src/application/projections/board-readers.ts:176-182`),
  which returns empty series and the sentence "Bottleneck unavailable: history is
  missing." The operator sees a plausible board, not a broken one.
- The metric-level `missingHistoryFallback` flag (`'null' | 'estimate' | 'skip'`)
  is a per-series hint about shape, not a statement about collection health,
  sample size or freshness. `ConcreteMetricsReadAdapter` also invents an instant
  from `new Date()` when there is no history at all
  (`src/application/projections/metrics-read-adapter.ts:154`), so an empty
  database still yields a series.

For a system whose purpose is deciding whether an experiment worked, these
states must be distinguishable: no missions completed; statistics unavailable;
statistics partially recorded; repository has history predating lifecycle
recording.

### Required fix

Return provenance alongside the metrics — repository, evaluated window, sample
size, newest event timestamp, count of rows rejected or missing identity, and
whether the adapter succeeded — and render an explicit unavailable/partial state
in the board instead of zeros and empty series. Count and expose recording
failures rather than discarding them; keep the recorder non-blocking.
<!-- SECTION:DESCRIPTION:END -->
