## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The board's statistics mix data from every repository the operator has ever run,
because repository identity is dropped between the domain event and storage.

- `LaneTransitionEvent` carries a `repositoryId`
  (`src/domain/board-event.ts`), and the recorder is handed a real value at the
  call site (`src/adapters/backlog/backlog.ts:797`,
  `repositoryId: repositoryId(rootDir)`).
- `BoardLaneEventEntry` has no repository field
  (`src/application/ports/operation-history.ts:15`), the `board_lane_events`
  table has no repository column
  (`src/adapters/sqlite/migrations/0003-board-lane-events.sql:32`), and
  `eventToEntry` silently drops it
  (`src/application/recording/board-event-recorder.ts:62`).
- The reverse mapping fabricates an empty identity —
  `repositoryId: '' as never` (`src/application/recording/board-event-recorder.ts:92`)
  — under a comment that claims the mapping is 1:1.
- The database is a single operator-global file at
  `<PARALLIX_HOME>/parallix.db` (`src/adapters/sqlite/database-path-resolver.ts`),
  so rows from all repositories share one table.
- `ConcreteMetricsReadAdapter.buildMetrics` then reads
  `laneEventRepo.findAll()` and `usageRepo.findAll()` with no repository
  predicate (`src/application/projections/metrics-read-adapter.ts:57`), and keys
  usage outcomes by `record.mission` alone
  (`src/application/projections/metrics-read-adapter.ts:108`) even though
  `usage_statistics` has a `repo` column and the CLI keys by repo+mission
  (`statsMissionKey`, `src/adapters/cli/commands/stats.ts`).

Consequence: the board shows a per-repository mission snapshot fused with global
telemetry. Lane ages, dwell times, throughput and the bottleneck sentence for
one repository can be driven entirely by missions belonging to another, and two
repositories that reuse the same task id (common with `task-NNNN` slugs) collide
outright.

A second, related defect: three writers use three incompatible repository keys
for the same repository, so the two halves of the statistics cannot be joined at
all.

| Writer | Key | Value for this repo |
| --- | --- | --- |
| Lane events (`backlog.ts:797`) | `repositoryId(rootDir)` | absolute path, differs per mission worktree |
| Usage rows (`stats.ts:120` `resolveStatsRepoName`) | `product.name` from `workflow.config.json`, else `path.basename(rootDir)` | `parallix` |
| Board projection (`concrete-git-read-adapter.ts:56`) | repo name parsed from `remote.origin.url` | `parallix` |

The lane-event key is a path (unstable across worktrees), the usage key is a
product label (shared by every clone and fork, and degrading to a worktree
directory name when `product.name` is unset), and the board key is a Git remote
name. No two of them agree by construction, so per-repository scoping cannot be
implemented until one identity is chosen and all three writers use it.

### Required fix

Add repository identity to the lane-event storage contract end to end (schema
column, index, port field, both mapping directions), record a stable repository
id rather than a worktree path, and make every board metrics read scope its
lane-event and usage rows to the repository the projection is being built for.
Existing rows must be migrated or explicitly marked as unattributed rather than
silently attributed to whichever repository is being viewed.
