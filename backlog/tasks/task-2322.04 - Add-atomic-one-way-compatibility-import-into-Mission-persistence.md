## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Provide an explicit, bounded bridge from existing operational records to checked Mission aggregates. The import exists only to establish the database before cutover: it materializes and validates domain values first, reports ambiguity without mutating either side, and commits the complete import atomically. It is not a task-catalog migration, a source-repair tool, an exporter, a synchronization mechanism, or a routine command fallback.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Dry-run discovers all legacy records needed for Mission, CheckpointData, and Review and reports exact source, target Mission identity, validation errors, conflicts, and omissions without writing.
- [ ] #2 Apply validates the complete candidate set before a single database transaction and leaves the database unchanged when any record is invalid or ambiguous.
- [ ] #3 Repeated apply is idempotent, records schema and import provenance needed to explain the result, and refuses to overwrite a divergent existing Mission.
- [ ] #4 Source task files, checkpoint artifacts, review-state files, and NEL records remain byte-for-byte untouched; no repair, normalization, deletion, or export occurs.
- [ ] #5 A pre-import backup and tested restore path recover the prior database after an interrupted or rejected import.
- [ ] #6 The importer invokes checked domain construction and Mission repository ports rather than inserting inferred rows or issuing SQL from command code.
- [ ] #7 No production read or write is redirected and no dual-write, shadow-write, background import, or file fallback is introduced.
<!-- AC:END -->
