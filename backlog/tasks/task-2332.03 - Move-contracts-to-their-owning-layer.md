## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Separate application capabilities from SQLite implementation contracts. Currently `adapters/sqlite/ports.ts` contains actual use-case ports that belong in the application layer, and application contracts carry SQLite-specific terminology (`sqlite`, `table`, `row`, `legacy-storage`) that leaks implementation details.

**Scope:**
- Move actual use-case ports out of `adapters/sqlite/ports.ts` into the application layer.
- Keep SQL records, migration ledgers, import rows and database mechanics adapter-internal.
- Remove `sqlite`, `table`, `row` and `legacy-storage` terminology from application contracts.
- Replace implementation identities such as `'sqlite' | 'compatibility'` with semantic results where needed.

**Target organization:**
```
application/ports/
  mission-store.ts
  mission-measurements.ts
  operator-preferences.ts
  repository-catalog.ts
  agent-blocklist.ts
  operation-history.ts
```

Application services compile against technology-neutral contracts. SQLite adapters implement those contracts.
<!-- SECTION:DESCRIPTION:END -->
