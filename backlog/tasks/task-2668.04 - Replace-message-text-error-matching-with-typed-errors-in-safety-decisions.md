## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Some workflow decisions are made by inspecting error message text. The clearest example is `isReviewerPoolExhausted` in `src/application/handoff-command-use-case.ts`, which decides whether review may fall back to self-review using `message.includes('exhausted') || message.includes('No agents available')`. Self-review fallback is a trust boundary: rewording an error message elsewhere would silently change whether a change gets an independent review. About 8 such message or stderr `.includes` / `.match` sites exist in `src/` at review time.

The outcome is that every decision affecting review independence, lifecycle transitions, or failover depends on an explicit error type or discriminated result from the producing port, never on human-readable text. Text matching remains acceptable only where Parallix parses third-party agent CLI output it does not control (for example usage-limit detection); those sites should be named and isolated in the adapter that owns that CLI.

If introducing typed errors changes an application port contract, follow the AGENTS.md rule for port changes: present evidence and alternatives and get an operator decision first.
<!-- SECTION:DESCRIPTION:END -->
