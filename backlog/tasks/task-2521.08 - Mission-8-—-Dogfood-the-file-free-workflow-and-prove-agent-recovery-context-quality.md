## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Part of wave TASK-2521 (read its architectural constraints and mandatory agent-slop checks; they apply here).

Depends on: Mission 7 (TASK-2521.07).

Purpose: prove that cleanup did not merely make tests green while breaking real agent usability.

### Required scenarios

Exercise the new architecture on Parallix itself.

1. **Fresh Quick Flow Mission**
   * create/select Mission with local SQLite task provider;
   * execute;
   * handoff/integrate;
   * assert zero Git-tracked workflow metadata created.
2. **Full Mission with checkpoint evidence**
   * fresh agent retrieves Mission context via supported `px` interface;
   * records real Goal Check evidence through supported interface;
   * handoff consumes DB-backed evidence;
   * no CP file is needed.
3. **Review REQUEST_CHANGES loop**
   * reviewer records findings;
   * implementer receives prior findings/context without review-event files;
   * implementer resolution persists;
   * next reviewer sees the correct prior state.
4. **Restart/recovery**
   * stop between meaningful lifecycle steps;
   * restart Parallix;
   * fresh process/agent reconstructs its required context from authoritative state plus current external observations;
   * no repository workflow file is required for recovery.
5. **Fresh-agent discoverability**
   * start from only the Mission slug and `px --help`;
   * verify the supported path to context and evidence commands is discoverable;
   * agent prompt must not need tribal knowledge of SQLite schema or old file locations.
6. **Trust failure**
   * attempt handoff with missing required checkpoint evidence;
   * prove fail-closed/send-back behavior;
   * prove no synthetic CP/evidence file is generated.
7. **Repository-noise check**
   * compare target repository before/after the representative runs;
   * product changes are allowed;
   * workflow-only Git-tracked files created because the missions occurred must equal zero.
<!-- SECTION:DESCRIPTION:END -->
