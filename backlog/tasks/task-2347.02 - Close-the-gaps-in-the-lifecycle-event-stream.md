## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Lifecycle statistics are reconstructed from `board_lane_events`, but several
lifecycle state changes never reach that table, so the event history cannot be
replayed into a correct lane history.

Known gaps:

- **No backlog-entry event.** `MissionIntakeService` creates a mission whose
  initial status is `backlog` and persists it with `this._store.save(mission, null)`
  (`src/application/mission-intake-service.ts:83`) without emitting a lane event.
  A mission that sits in backlog and has never transitioned has no `enteredAt`
  timestamp at all, so it is invisible to every event-derived age, dwell and
  flow calculation.
- **No integration or closure event.** `MissionIntegrationService.decideIntegration`
  and `close` both use `this._store.save(...)`
  (`src/application/mission-integration-service.ts:52` and `:70`) rather than
  `saveWithTransition`, so the `integration → done` transition and the closure
  never produce lane history. Only `MissionLifecycleService.transition`
  (`src/application/mission-lifecycle-service.ts:95`) takes the transition-aware
  path.
- **Two competing write paths.** The path that actually records events in
  production today is the markdown transition in
  `src/adapters/backlog/backlog.ts:750-830`, which opens its own database,
  builds its own event and swallows every failure, in parallel with the
  aggregate path in `SqliteMissionStore.saveWithTransition`. The two can produce
  different agents, timestamps and idempotency keys for the same transition.
- **Idempotency key is time-derived.** The key is
  `${slug}-${from}-${to}-${Date.now()/1000|0}` (`src/adapters/backlog/backlog.ts`),
  so the same logical transition replayed a second later appends a duplicate row
  while a genuine repeat inside the same second is dropped.

Consequence: backlog age is unknowable, done transitions are missing so
throughput and end-to-end cycle time cannot be derived from events, and the
final lane dwell of every mission is truncated.

### Required fix

Make every lifecycle state change flow through one transition-aware persistence
operation that writes the aggregate and the lane event atomically, including
mission creation (entry into `backlog`), `integration → done` and closure.
Replace the wall-clock idempotency key with one derived from the transition
identity. Retire or delegate the ad-hoc recording block in `backlog.ts` so a
transition has exactly one recording path.
