## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Perform the single production authority switch for the complete Mission domain after import and all use cases are ready. The cutover is an operational gate, not another broad redesign: verify a complete import, select the SQLite Mission repository for every command and projection in one release, and remove the file-backed lifecycle authority at the same time. External planning tasks, Git observations, configuration, and artifacts remain explicitly separate boundaries.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A preflight gate proves the import is complete and unambiguous for all discoverable Missions and blocks cutover with an actionable report otherwise.
- [ ] #2 One composition-root change selects SQLite for every Mission read and write, including current state, CheckpointData, Review, structured NEL data, and LaneTransitionEvent history.
- [ ] #3 Task lifecycle fields, checkpoint structured state, review-state JSON, and NEL JSON are no longer read, written, reconciled, or used as fallback authority by default commands, status, TUI, or shared board projections.
- [ ] #4 External task material is accessed only through the explicit planning or intake boundary; edits after materialization cannot change Mission lifecycle state.
- [ ] #5 Database unavailability, constraint failure, or stale version fails the requested operation without writing legacy files or partially performing dependent external effects.
- [ ] #6 End-to-end tests cover cold start after import, restart, concurrent stale writers, every supported Mission transition, review and integration flow, and direct mutation of retired legacy files.
- [ ] #7 The legacy compatibility Mission adapter is deleted or made unreachable from production composition, and the architecture inventory has no remaining Mission-domain exceptions.
<!-- AC:END -->
