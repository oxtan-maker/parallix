## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add the operator-database persistence boundary for the checked Mission aggregate without changing production authority. Persist the aggregate as defined by the domain, including its current CheckpointData and Review state, and keep repository observation separate through RepositoryId and KnownRepository. The adapter must provide concurrency and transaction semantics strong enough for the later one-step cutover; it must not reproduce a task catalog or invent schema-led entities.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Mission round trips preserve every checked field and nested value required by current commands and projections, including repositoryId, status and rawStatus, assignee, labels, closedAt, CheckpointData, and Review.
- [ ] #2 Mission writes use optimistic concurrency or an equivalent checked version contract, and stale writers fail without partially changing the aggregate.
- [ ] #3 A Mission transition and its LaneTransitionEvent commit in one transaction; failed persistence leaves neither a new current state nor a history-only event.
- [ ] #4 RepositoryId is the stable Mission reference while KnownRepository stores observed path and display metadata as a replaceable cache rather than identity authority.
- [ ] #5 Database initialization and forward migration are proven for clean install, prior-schema upgrade, checksum mismatch, interrupted migration, backup, restore, and concurrent access using isolated fast fixtures.
- [ ] #6 Application and UI layers use repository ports and cannot import the SQLite adapter or issue SQL.
- [ ] #7 No production command is switched, no legacy source is read or repaired, no shadow write occurs, and no table is added for Attempt, task catalog, worktree, process, or another unchecked entity.
<!-- AC:END -->
