## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The board's throughput and history-shaped series are not functions of time and
do not filter for completion.

- `weeklyThroughputSeries` (`src/application/projections/metrics.ts:252`) returns
  a single point `{ at: 'available-history', value: outcomes.length }` — the
  number of missions with any telemetry, not completions in a week. The TUI
  prints it as `Weekly throughput`
  (`src/interfaces/tui/flow-panel.tsx:42`, `:55`) and the bottleneck sentence
  calls it `N completed this week`
  (`src/application/projections/metrics.ts:298`).
- `usageRecordsToOutcomes` (`src/application/projections/metrics-read-adapter.ts:94`)
  never filters on `closed === 'yes'` and never requires a completion timestamp,
  so active and in-review missions are counted as completions. The CLI already
  does this correctly (`src/adapters/cli/commands/stats.ts:791`).
- `throughputSeries` (`src/application/projections/metrics.ts:186`) contains the
  stub `outcomes.filter(() => true).length` — the same constant at every instant.
- `medianStateTimes` (`:108`) and `reviewLoopRateSeries` (`:212`) also compute
  from the whole outcome set at every instant, so a mission that closed in June
  influences the value plotted for May. `MissionOutcome`
  (`src/domain/usage.ts`) has no `closedAt`, so the correct predicate cannot even
  be expressed with the current contract; `CompletedMissionStatistics` does carry
  `closedAt`.
- `cumulativeFlowSeries` (`:137`) returns `state.size` — the total mission count,
  identical at every instant — rather than a flow measure.

Consequence: the number the board presents as weekly delivery rate is a lifetime
count of missions with telemetry, and every "historical" line is a flat line of
today's value.

### Required fix

Give the board projection an outcome contract that carries `closedAt` (and
`createdAt`), restrict completions to genuinely closed missions, and make every
series evaluate its value using only data available at that bucket:
weekly throughput = missions whose `closedAt` falls inside that week; rolling
metrics use `bucketStart <= closedAt < bucketEnd`. Remove the `filter(() => true)`
stub and either implement `cumulativeFlow` as a real cumulative measure or delete
it along with the unused `wipAtTime`/`wipSeries` exports. Relabel any metric whose
meaning changes.
<!-- SECTION:DESCRIPTION:END -->
