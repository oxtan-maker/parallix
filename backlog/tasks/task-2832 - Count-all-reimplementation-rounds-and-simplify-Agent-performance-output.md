## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace the misleading Agent performance fix metric with the operator's requested all-cause reimplementation count and remove the diagnostic noise from the default report.

Operator reproduction: completed Missions for 2026-10-28 through 2026-11-03 show codex: 19 deliveries, average authored PR fix rounds 0.86, PR fix n 7; custom: 2 deliveries, average 0.00, PR fix n 1. Ownership coverage is 21/21, but review-fix coverage is 11/21. The operator expects substantially more returns when inspecting Forgejo. That expectation is a hypothesis to verify, not a target or multiplier. TASK-2829 was accidentally integrated before the operator considered it ready; this mission must be independently evidenced. The statistics implementation and prior requirements are in TASK-2818; its narrow coding-defect/cause filters do not define this new metric.

Required output: use Model and # missions as implementer; replace Average authored PR fix rounds and PR fix n with a single integer column named # reimplementation rounds. This is the total count for that agent in the selected completed-mission population, not an average over a selectively observed subset. Remove Delivery ownership coverage, Review-fix mission coverage, the delivery/measurement explanatory paragraph, and the entire Repair/re-review cause / Obligations table from default weekly and range output. Apply the same metric to current and previous periods. Preserve resource/spend units and their meaning exactly; fix model attribution as specified below.

Counting contract: count each distinct round in which delivered work is sent back for reimplementation after the initial implementation, regardless of cause or sending stage: pre-review verification/contract gates, PR reviewer feedback, human requests, integration gates, infrastructure, pushback, or an unknown cause. Unknown cause must never exclude an established return. Distinct returns in separate cycles count separately even when the revision, gate or finding is unchanged. Multiple findings, duplicate events, provider/local copies, retries and repeated polling representing one return count once. A failed check with no return to implementation, an initial implementation, an approval, or a mechanical re-review without a return is not a reimplementation round. Trace actual workflow transitions and repair launches, including returns before a PR/review round exists; do not assume review-round-count-minus-one captures the contract.

Preserve truthful implementer attribution when A is replaced by B: attribute returns to the implementer responsible for the work sent back, not automatically to the repair executor or final delivery owner. Keep final ownership for delivery counts. Preserve unassignable provenance explicitly without inventing an agent. An established return with an unknown cause is a known count; absent historical evidence is a different problem and must not become zero or be silently omitted from a reassuring total. If the full count cannot be established, use an honest unavailable/incomplete value in the metric cell rather than reintroducing the removed diagnostic sections.

Inspect and reuse the existing owners before implementing: review-statistics.ts, the review-statistics-evidence adapter, statistics report selection/aggregation/rendering, recording and cohort consumers, and existing lifecycle/repair persistence. Reconcile all affected production consumers through one application-owned calculation and typed ports. Remove superseded authored-fix algorithms, cause-based exclusions, obsolete fields and redundant tests while preserving distinct behavioral assertions; do not wrap the old calculation in another metrics subsystem. A migration must not silently relabel old narrower stored values as all-cause counts.

Correct historical reporting as well as future writes. Reconcile all 21 completed Missions in the reported week against retained workflow history and paginated real Forgejo reviews/comments. Read provider history through existing boundaries. Produce a reviewable per-mission audit with counted return identities, source evidence, attribution, deduplication and explicitly unreconstructable gaps, and reconcile those totals to the displayed per-agent counts. Validate reconstruction idempotently on an isolated database copy first; preserve raw history and do not silently rewrite the operator database or mutate PRs. Evidence belongs in mission artifacts, not verbose product output. Do not assert a corrected average or promise 5-10 rounds before this audit.

Read ADR 0057 and extend the existing owning suites with focused parent-red/fixed-green reproductions. No gate additions/restorations, budget inflation or convenience integration suite. Unit headroom remains 500 ms; any added/modified integration test must complete within 3.5 seconds. Manually exercise the built production reporting path end to end against isolated state, including gate/PR/human returns, repeated cycles, agent replacement, historical reconstruction and weekly/range output. Update only necessary live metric documentation. This task creates the mission specification; implementation and integration are separate operator actions.

Additional operator requirement: repair model attribution across performance and spend reporting. The supplied 2026-10-28 through 2026-11-03 spend table contains concrete models claude-opus-5-5, claude-sonnet-5-5, gpt-6.1-sol and qwen3.8-flash-next-iq3_s, alongside generic codex/custom rows and two separate mixed rows ($2.47 review spend and 170m review runtime). Model comparisons must show concrete recorded model identities, never codex, claude, custom or mixed as model names. Use Model as the identity column in model comparison tables. Preserve distinct actual models within one runner family and attribute each stage's resource measurements to the model that performed it; a reviewer's model must not overwrite the implementer's model, and the final delivery model must not absorb earlier models' repair rounds. Preserve the earlier per-author replacement rule at model granularity. Do not guess a model from current runner configuration, family name or the latest model on a mission. When evidence cannot establish a model, account for unattributed amounts/counts explicitly as unavailable model attribution outside the named-model comparison, with one concise indication; do not silently drop them, invent a specific model or substitute another generic model row.

Current inspected sources give concrete investigation leads, not a completed historical diagnosis: sameStatsIdentity in statistics-row.ts omits model and reviewer identity, mergeLabel turns differing nonempty model labels into mixed, and StatsRecordingUseCase.accumulateStage combines those rows. summarizeAgentStageSpend groups by actor/model and falls back to generic actor names; assignCompletedMissionOwners deliberately clears model for performance grouping. Trace ingestion, recording identity, persistence/upsert keys, accumulation, historical reconstruction and all report consumers before changing code. Repair the owning contracts end to end; merely hiding generic rows or renaming mixed loses data and fails acceptance. Extend the historical audit to reconstruct the supplied mixed/generic rows from retained per-run telemetry where possible, reconcile attributed plus unattributed resources, and demonstrate future writes keep model identity through model switches within the same mission/stage and reviewer switches.

NON-NEGOTIABLE UNIT CONTRACT: the model-attribution repair must preserve the existing resource units, formatting meanings and aggregation rules. Claude/Anthropic and Mistral/Vibe spend remains dollars, summed per stage and total, with parentheses showing each stage's share of that model's dollar total. Custom/local runtime remains minutes, summed per stage and total, with parentheses showing each stage's share of that model's runtime total. Codex/OpenAI quota remains the recorded percentage quota peak per stage and the maximum peak in total / peak, never summed quota, consumption, delta, dollars, minutes, or a stage-share percentage. Missing quota remains unavailable (—), never a fabricated 0%; an evidenced real 0% remains valid. Do not convert or unify units, change peak to consumption, alter percentage denominators, or replace the existing resource table with a new metric. Actor/provider evidence selects the resource contract; changing the displayed identity to a model must not change that selection. The explicitly requested replacement of authored PR fix averages with integer reimplementation counts is the only metric-unit change authorized by this mission.

Verification must retain regression assertions for the exact resource contracts while adding parent-red/fixed-green reproductions for model identity loss and generic fallbacks. Compare resource values before and after on isolated retained evidence: attributed plus explicitly unattributed dollar and minute totals must conserve the same measured amounts, and quota peaks must reconcile to original snapshots using max. Exercise the built recording-to-report path with two models under the same actor/stage, two reviewer models, generic/mixed historical records, genuinely missing model evidence, and missing versus measured-zero quota. No integration or live-data mutation is authorized by creating this task.
