## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Final migration: the remaining standalone bounce paths — the CLI rebase/integrate hook bounces and the handoff-time relaunches — move onto the rebound kernel (TASK-2377.03), leaving the kernel as the only agent-bounce path in the codebase.

**CLI paths:**

- `px rebase`: the hook-failure auto-bounce (currently in the rebase workflow with its own `rebase --continue` retry loop) becomes a `rebound` call; verify = retry `rebase --continue`. The conflict path (real merge conflicts) is unchanged — that is a conflict workflow, not a failure bounce.
- `px integrate`: the squash-commit hook bounce becomes a `rebound` call; verify = retry the squash commit. This runs on the production integrate implementation — the dead duplicate implementation is consolidated by TASK-2372, which this task depends on; if TASK-2372 leaves a delegating shim rather than deleting the file, this task deletes the leftover copy once it has no callers.

**Handoff paths (the `px active` handoff-and-review path):**

- The checkpoint-validation relaunch loop (local max-2 counter, not persisted) becomes a `rebound` call with `handoff-verification` reason; verify = re-validate checkpoints.
- The handoff-failure relaunch loop (local max-2 counter, gate output captured) becomes a `rebound` call; verify = re-run the automated handoff.
- The git-only repair (dirty worktree, behind main, no agent) stays outside the kernel — it is a repair, not a bounce.

**Resulting invariant:** no code path launches an agent "to fix a failure" except through the kernel. Every such launch is followed by a mandatory verify before the outcome is reported. New failure modes are added as one reason variant + one classifier rule + one verify callback at the site.

Out of scope: launcher-level agent-family failover (a different axis: selecting an eligible family, not fixing a failure — it stays in the agent launcher, though its ambiguous-null-success semantics fix lands with the kernel's launch rule in TASK-2377.03).
