## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Part of wave TASK-2521 (read its architectural constraints and mandatory agent-slop checks; they apply here).

Depends on: Mission 2 (TASK-2521.02).

Purpose: agents must become BETTER informed after repository metadata disappears, not worse.

### Work

Provide an application-owned Mission context projection usable by both humans and agents.

It must be able to expose the relevant combination of:

* Mission identity and lifecycle;
* goal/context;
* scope and constraints;
* refinement/NEL information;
* declared gates;
* latest checkpoint evidence;
* outstanding review findings;
* prior implementer resolutions;
* predecessor/dependency outcomes relevant to this Mission;
* relevant Git/revision observations;
* verification state where relevant;
* external task reference/context where available.

Add one discoverable CLI path for retrieving this information.

Preferred naming is a concise command consistent with the existing CLI; exact spelling may follow existing conventions, but acceptance requires that a user starting from:

```text
px --help
```

can discover how to retrieve full Mission context without knowing repository internals.

Support a machine-readable representation where appropriate so agents do not have to scrape human-formatted terminal output.

Likewise expose/discover supported application commands for recording evidence rather than asking agents to write durable workflow files.

Update the actual agent instructions/prompts/completion contracts used at runtime:

* do not tell agents to read `missions/<slug>/MISSION.md` as the source of Mission truth;
* do not tell agents to create `CP-N.md` as durable evidence;
* tell agents how to query current context;
* tell agents how to record checkpoint/evidence through supported `px`/application commands;
* tell review/implementer agents how prior findings/resolutions are supplied;
* explicitly state that repository workflow metadata is not the Mission database.

Update `px --help` and relevant subcommand `--help`.

Do NOT add a new README/index solely to repeat command help.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A fresh agent given only a Mission slug and `px --help` can discover the supported context command.
- [ ] #2 That command returns enough information to execute the Mission without inspecting `missions/**` or Backlog task files.
- [ ] #3 A machine-readable context form exists if agent integration requires structured consumption.
- [ ] #4 A fresh agent can discover how to record checkpoint/evidence without writing a CP file.
- [ ] #5 Runtime prompts no longer instruct agents to use retired workflow files as authority.
- [ ] #6 Tests assert the required context fields are present for execute/review/recovery scenarios.
- [ ] #7 No duplicate durable context document is introduced.
