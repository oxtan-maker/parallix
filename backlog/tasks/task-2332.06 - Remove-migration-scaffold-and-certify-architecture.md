## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Finish the migration; do not certify a partial architecture. After all prior missions
are integrated, this mission removes the temporary scaffolding **and the remaining
`src/platform/` production tree**. `platform` is not an architectural layer and
must not become an exception bucket for code that has not yet been re-owned.

Every production responsibility currently below `src/platform/` is in scope and
must be moved to its proper ports-and-adapters home. The migration is complete
only when the production source tree has no `src/platform/` directory or imports
of it. Preserve externally observable CLI behavior while changing ownership.

**Required final ownership:**

| Responsibility | Final home |
|---|---|
| Core business rules and value objects | `src/domain/` |
| Use cases, orchestration, and dependency contracts | `src/application/` and `src/application/ports/` |
| Concrete filesystem, Git, process, agent, Forgejo, Backlog, SQLite, and packaged-asset implementations | `src/adapters/` |
| CLI/TUI request translation and rendering | `src/interfaces/` |
| Object wiring only | `src/composition/` |
| Bootstrap and process exit only | `src/entry/` |

This includes every former `platform/runtime/lib` concern: command handlers,
review workflow, agent launchers, Git/worktree/process utilities, configuration
and storage access, verification, and architecture guards. It also includes
`platform/assets`: packaged runtime assets are outbound adapters, not a separate
layer. Split modules where necessary so application policy does not retain direct
Node, filesystem, process, Git, or provider dependencies.

**Scope:**
- Re-home every production module under `src/platform/` according to the final
  ownership table; then delete that directory.
- Replace relative imports and public entry wiring so no source or production
  build configuration refers to `src/platform/`.
- Remove the temporary dependency allowlist: all remaining edges must be valid
  canonical layer edges, checked across the whole production tree.
- Delete transitional re-exports and compatibility façades rather than preserving
  an old path as an alternate architecture.
- Remove task IDs, checkpoint labels, and obsolete migration commentary from
  production source.
- Update architecture documentation and directory READMEs to describe the final,
  platform-free layout.
- Validate representative flows end to end: `draft`, `active`, `retry/failover`,
  `review`, `integrate`, `statistics`, `CLI board`, and `TUI board`.
<!-- SECTION:DESCRIPTION:END -->
