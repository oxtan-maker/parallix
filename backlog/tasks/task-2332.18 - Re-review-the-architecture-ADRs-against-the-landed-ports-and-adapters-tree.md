## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ADR 0051 was written in 2026-07 to describe an intended UI-neutral application boundary, before the migration existed. The TASK-2332 series has since actually landed it: six canonical layer roots under `src/`, an executable dependency guard, command workflows re-homed into application use cases, and named cross-adapter rules. The ADR has not been revisited against that outcome, so it argues from a tree that no longer exists.

Its context section still reasons about `lib/commands/active.ts`, `lib/commands/stats-backfill.ts`, `lib/tools/backlog.ts` and a root `px.ts` — four files that were deleted in the migration — and cites 18 `file.ts:line-range` references into them. A reader cannot tell which parts of the ADR are still the active decision and which describe a starting condition that has been superseded by the work itself.

Implementing the ADR also surfaced decisions the ADR never made, and which are currently only encoded in guard code and a README: what distinguishes an adapter that uses several mechanisms from one that owns a workflow; whether cross-adapter dependencies are permitted at all or must always go through an application-owned port; and which layer owns request translation now that `src/interfaces/` exists.

This is a review-and-amend task, not a rewrite. Per the project convention, ADRs record current active decisions only: amend the owning ADR in place, do not accrete history, superseded-by clauses, or dated update sections. Where the landed architecture contradicts the ADR, the ADR is what changes unless the review concludes the implementation is wrong — in which case record that as a finding and raise a separate task for the code.
