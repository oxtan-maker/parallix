## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The production-tree scan classifies every module by architectural responsibility and reports unclassified files; moving or renaming a monolith cannot make it pass by directory placement alone.
- [ ] #2 Cross-adapter dependencies are constrained by named package-level rules or application-owned ports rather than the blanket adapters-to-adapters permission.
- [ ] #3 A fixture that restores multi-integration command orchestration under an arbitrary src/adapters path fails the guard without modifying guard configuration.
- [ ] #4 Application, interfaces, composition, entry, domain, and adapter ownership rules are enforced across the complete production tree with zero allowlist exceptions.
- [ ] #5 Mutation tests demonstrate that prohibited direct imports, hidden service-location, adapter-owned workflow sequencing, and new unclassified production modules each make the architecture gate fail.
- [ ] #6 Guard diagnostics identify the offending file, responsibility rule, and expected owner so failures are actionable.
<!-- AC:END -->
