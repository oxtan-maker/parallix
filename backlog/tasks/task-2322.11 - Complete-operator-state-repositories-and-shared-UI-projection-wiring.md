## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Finish the database-owned operator state needed by all presentation surfaces after Mission cutover. Wire KnownRepository observations, UI preferences, AgentBlock state, and operational history through application queries and one production composition root. CLI, TUI, and the planned web board must consume the same contracts; none may initialize SQLite, inspect persistence files, or reconstruct authority independently.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 KnownRepository observations are stored and queried as replaceable metadata keyed by RepositoryId; path changes and rediscovery cannot create a second Mission identity.
- [ ] #2 UI preferences use the checked database repository in production and survive restart without a memory or JSON authority fallback.
- [ ] #3 LaneTransitionEvent and other approved operational history are written only through application behavior, and current Mission state is never reconstructed from history.
- [ ] #4 CLI, TUI, and shared web-board projection contracts return consistent Mission, repository, agent-block, preference, and history data from application queries.
- [ ] #5 Presentation and command modules receive ports from one composition root and cannot open the database, initialize migrations, issue SQL, or inspect durable files.
- [ ] #6 Production in-memory repositories and adapter-specific projection shortcuts are removed or confined to tests.
- [ ] #7 Tests cover repository path change, preference restart, event ordering, unavailable history, blocked agents, and database failure without real Forgejo or agent launches.
<!-- AC:END -->
