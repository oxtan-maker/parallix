## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Even with correct formulas, the board cannot answer the question the statistics
exist for: did a given change to the workflow improve mission delivery?

`ConcreteMetricsReadAdapter.usageRecordsToOutcomes`
(`src/application/projections/metrics-read-adapter.ts:94`) builds a `MissionOutcome`
carrying only mission id, repository id, a summed duration and a fix-round count,
and sets `runs: []`. Labels, implementer, model, provider, tokens, cost, tool
calls and `closedAt` are all discarded, even though `CompletedMissionStatistics`
(`src/domain/usage.ts:114`) already models them and `usage_statistics` stores
them. The board therefore has no dimension to slice by, and no way to attach a
sample size to a comparison.

### Required fix

Extend the statistics projection from task-2347.08 with cohort comparison: group
completed missions by an experiment dimension (mission label first, then
model/provider/implementer and date range) and report per cohort, always with
`n`:

- completed missions
- median and p75 end-to-end cycle time
- median dwell in `active` and in `review`
- review bounce rate (`review → active` transitions per mission entering review)
  and median fix rounds
- tokens, agent runtime and cost per completed mission
- net engineering lines

Expose it through both `px stats` and the board so a cohort comparison is never
shown without its sample size.
<!-- SECTION:DESCRIPTION:END -->
