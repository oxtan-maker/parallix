## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Part of wave TASK-2521 (read its architectural constraints and mandatory agent-slop checks; they apply here).

Depends on: Mission 1 (TASK-2521.01).

Purpose: remove the architectural need for `MISSION.md` and checkpoint documents before deleting any files.

### Work

* Identify the Mission execution fields actually consumed by current execution/refinement/handoff/review flows.
* Add only those bounded concepts to the existing Mission/application model.
* Expected examples include, where current consumers prove they are needed:
  * goal;
  * why/context;
  * scope;
  * constraints;
  * refinement signals;
  * mission-specific declared gates;
  * dependency/predecessor references or outcomes required for execution.
* Do NOT add arbitrary fields simply because historical `MISSION.md` sections exist.
* Do NOT persist the historical document as an opaque Markdown blob.
* Add SQLite migration(s) through the established migration mechanism.
* Provide application-owned read/write contracts for the execution context.
* Complete checkpoint recording so `CheckpointData` / Goal Check evidence can be created directly through application behavior without a CP file round-trip.
* Preserve large/unbounded evidence by reference where ADR 0053 requires that boundary.
* Ensure optimistic concurrency/stale-write semantics remain consistent with existing Mission persistence.
* Add round-trip/restart tests: record context/evidence, close process/store, reopen, retrieve identical domain facts.
