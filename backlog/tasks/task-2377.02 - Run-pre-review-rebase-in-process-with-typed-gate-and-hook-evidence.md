## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The pre-review rebase step (`rebaseBeforeReviewRound` in the review-loop path) spawns a nested `px rebase --push` CLI subprocess and communicates only through its combined stdout text. Two defects follow:

1. **Misclassification.** When the rebase succeeds but the push-time verification gate fails, the gate's full output (a unit-suite run can contain the words `pre-push` or other hook-like text) flows into the parent's captured output. The parent's own hook regex then classifies a genuine gate failure as a Git hook failure — wrong failure class, wrong budget, wrong fix prompt. This is the exact chain behind the task-2369.13 incident.
2. **Split-brain budget.** The nested CLI independently runs its own hook-failure bounce from the same persisted retry counter the parent reads. Two processes consume one budget without either knowing what the other consumed, so the parent's bounce-vs-strand decision is nondeterministic.

Fix:

- Run the pre-review rebase **in-process** through the existing `RebaseWorkflowPort` (the port and its adapter already exist); no `child_process` spawn on this path. The nested CLI remains available as the standalone `px rebase` command — only the review-loop consumer stops spawning it.
- Propagate **typed evidence** instead of text: the rebase step and the push-time verification gate return structured results (rebase state, the failing git operation, gate area, command, exit code, stdout, stderr). Hook-failure identity comes from which git operation failed with a hook error, not from a regex over combined output.
- Delete the parent-side hook regex copy in the review-loop rebase adapter. The pre-review path's failure input to the rebound kernel (TASK-2377.03) is the typed result.
- The misleading "Hook rebounce available in CLI rebase command" log (which described a rebounce that was already happening inside the subprocess) disappears with the subprocess.

Out of scope: the standalone `px rebase` command's own behavior and its hook-bounce path (migrated by TASK-2377.05); the kernel itself (TASK-2377.03).
