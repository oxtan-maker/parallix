## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Before changing authority, make every durable-state boundary visible and enforceable. Inventory all production readers and writers for ADR 0053 domain concepts, classify the file-backed boundaries that remain legitimate external inputs or artifacts, and add characterization and architecture checks that assign every legacy path to a later cutover task. This task changes no runtime authority and deliberately excludes the task-catalog repair, byte-faithful aggregate import, shadow-write, and all-at-once command rewrite approaches attempted by TASK-2315 and TASK-2316.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 An executable inventory covers Mission, CheckpointData, Review, MissionOutcome, AgentRunMeasurement, KnownRepository, SessionMarker, LaneTransitionEvent, AgentBlock, UI preferences, task intake, Git observations, configuration, secrets, and large artifacts, including every current default and compatibility reader or writer.
- [ ] #2 Every inventoried production read and write is classified as database-owned domain state, explicit one-way legacy input, external fact or intake, configuration or secret, generated artifact, or forbidden persistence; every temporary exception names the task that removes it.
- [ ] #3 Fast characterization tests preserve the observable CLI, TUI, and shared board-projection behavior needed during migration without invoking real Forgejo, agents, or expensive commands.
- [ ] #4 An architecture test fails when application or UI code issues SQL directly or introduces an unclassified durable file read or write, while allowing only explicitly registered staged exceptions.
- [ ] #5 The inventory distinguishes external task authoring and Git facts from Mission lifecycle authority, and does not repair, normalize, or mutate source task files.
- [ ] #6 No production authority is switched, no source format is repaired, and no dual-write or shadow-write path is introduced by this task.
<!-- AC:END -->
