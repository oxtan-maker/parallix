## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parallix has two independent implementations of mission statistics over the same
database, and they disagree.

- `src/adapters/cli/commands/stats.ts` (2563 lines) owns the CLI semantics:
  completion filtered by `closed === 'yes'` (`:791`), mission identity keyed by
  repo+mission (`statsMissionKey`), window filtering (`rowInWindow`), and
  deliberate handling of the rollup-versus-stage row split
  (`computeAgentMissionGroups`, `:836-860`).
- `src/application/projections/metrics.ts` plus
  `src/application/projections/metrics-read-adapter.ts` reimplement all of it
  differently for the board, with none of those rules.

So `px stats` and the board can report different numbers for the same run, and
every correctness fix has to be made twice. Business semantics also live in a
CLI adapter, contrary to the boundary ADR 0051 the rest of the codebase follows.

Two further defects belong with this consolidation:

- **Unsafe time bucketing.** `deriveInstants` truncates with
  `t.occurredAt.slice(0, 13) + ':00:00Z'`
  (`src/application/projections/metrics-read-adapter.ts:142`), which reinterprets
  rather than converts any timestamp carrying a non-UTC offset (legacy imported
  rows), and mixes those hour buckets with usage `date` values expanded to
  midnight (`:149`). Bucketing must parse to an instant first, then bucket in UTC.
- **Quadratic recomputation.** Every series maps over all instants and rescans
  all transitions or all outcomes per instant
  (`metrics.ts:137-174`, `:186-227`), and instants grow with event history — the
  board's metric cost grows with the square of recorded history. The lane
  intervals from task-2347.03 make a single ordered pass sufficient.

`buildBoardMetrics` (`src/application/projections/board.ts:164-212`) additionally
dispatches ten positional arguments through overloads with unchecked casts
(`as MetricSeries`, `as LaneMetricSeries`), so a mis-ordered argument is a silent
metric swap; it should take a named object.

### Required fix

Extract one statistics application service that owns mission identity,
completion, windowing and every metric definition, and make both `px stats` and
the board projection thin presentation adapters over it. Fix UTC bucketing and
the quadratic evaluation in the shared implementation, and replace the positional
`buildBoardMetrics` overloads with a named-field input.
