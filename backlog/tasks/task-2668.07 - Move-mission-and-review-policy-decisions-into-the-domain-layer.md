## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The dependency direction is clean (application and domain import no adapters), but the domain is thin: about 2.9k lines in `src/domain/` versus about 24k in `src/application/` and about 44k in `src/adapters/`, and one domain file (`review.ts`) holds about a third of it. Business policy such as when a mission may advance, when review may fall back to self-review, when a rebound returns to active versus stays in integration, and which gate results block integration is spread across use cases (`handoff-command-use-case.ts`, `rebound-kernel.ts`, `rebase-workflow.ts`) and adapters (`review-commands.ts`, `review-state.ts`).

The outcome is that the key lifecycle and review policies are pure domain functions or value objects, unit-tested without doubles, and use cases only orchestrate ports around them. This makes the architecture claims in ADR 0051 and ADR 0053 visible in the code and makes the policies reviewable in one place.

Start by producing an inventory of policy decisions that currently live outside the domain, with proposed owners, and present it to the operator before moving code. If this changes application ports or composition authority, AGENTS.md requires an explicit operator decision first.
<!-- SECTION:DESCRIPTION:END -->
