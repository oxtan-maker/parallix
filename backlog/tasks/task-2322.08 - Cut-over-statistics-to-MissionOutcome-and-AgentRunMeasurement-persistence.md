## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace stats.csv as live authority with the checked MissionOutcome and AgentRunMeasurement persistence boundary. Migrate historical rows explicitly, route every runtime measurement writer and reader through application ports, and preserve current CLI and UI metrics without retaining an implicit file fallback. A CSV path may remain only as an explicit read-only legacy import input, never as the default store or an output target.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Every runtime producer of active, stage, review, handoff, integration, and completion measurements persists checked AgentRunMeasurement or MissionOutcome data through application ports.
- [ ] #2 The default stats command and all TUI or shared board metrics query SQLite and preserve characterized filtering, totals, grouping, formatting, and missing-data behavior.
- [ ] #3 Historical CSV import has dry-run and atomic idempotent apply modes, reports malformed and ambiguous rows without partial writes, and never modifies the source CSV.
- [ ] #4 An explicit legacy CSV option is read-only input to import or analysis; no default execution resolves stats.csv, writes CSV, or silently falls back when SQLite is unavailable.
- [ ] #5 Legacy default file writers and helpers, including save, upsert, and resolve-stats-path behavior, are removed from production code and help text identifies the database authority.
- [ ] #6 No Attempt or other per-run entity is inferred in adapter code; any identity required by current measurements must have been decided and checked by TASK-2322.02.
- [ ] #7 Architecture and regression tests prove zero unclassified stats.csv reads or writes and cover restart, duplicate import, concurrent measurement updates, and database failure with fast isolated fixtures.
<!-- AC:END -->
