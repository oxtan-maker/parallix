## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Base: TASK-2500. Mission 2 of 6. Implement `github-publish`: Parallix keeps integrating missions locally at full speed while GitHub independently verifies each resulting integration commit before that commit is allowed to advance remote `main`.

GitHub latency becomes publication latency, not development latency.

FLOW:
```text
origin/main = P
local main  = P
P -> A -> B -> C            (local main advances through integrations)
A/B/C each -> verification ref (exact SHA unchanged)
once A verified AND A is direct next unpublished descendant of origin/main -> advance origin/main to A
then B, then C
```
Local development continues ahead of GitHub verification; earlier commits may still be checked while later ones integrate.

INVARIANT: remote `main` advances only through the highest contiguous sequence of externally verified local integration commits.
```text
P -> A -> B -> C -> D
A ✅  B ✅  C ❌  D ✅
```
May advance through B; must NOT skip C and publish D.

DEPENDENCY ORDER: base TASK-2500. Depends on Mission 1 (TASK-2500.01) for the shared abstraction. Can run in parallel with Mission 3 (TASK-2500.03).
<!-- SECTION:DESCRIPTION:END -->

## Mission Requirements

- Durable representation of at least: locally integrated, external verification pending, externally verified, published, external verification failed. Internal state/evidence is acceptable; do not necessarily add board lanes.
- The exact locally-generated integration commit must be the commit GitHub verifies and later receives on `main`. No GitHub-side squash/rebase/recreation of that commit.
- Publication invariant: remote `main` advances only through the highest contiguous sequence of externally verified local integration commits. No force-push of protected `main`. Fail closed if `origin/main` is no longer the expected ancestor.
- Recovery for: verification failure; GitHub unavailable; verification ref already exists; local main ahead by multiple missions; remote main unexpectedly moved; verification completed out of order; retry after transient GitHub failure.
- Operator status exposes: local integration head, published head, missions awaiting verification, missions verified but blocked behind an earlier mission, failed verification.
