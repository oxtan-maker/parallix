## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Part of wave TASK-2521 (read its architectural constraints and mandatory agent-slop checks; they apply here).

Depends on: Mission 1 (TASK-2521.01) and Mission 3 (TASK-2521.03), which is integrated.

The Mission aggregate is the only self-hosted task record. There is no separate
task provider, task port, task table or task CLI. TASK-2521.03 removed the
unused `TaskSource` port and made the Mission contract DB state: `refine`
now requires a brief, a scope, success criteria, a checkpoint plan, a gate, a
predicted NEL bucket, and a reproduction test for a bug mission.

This mission does two things:

1. **Finish the explicit legacy importer (`px import-legacy`) under the new
   contract rule.** The importer landed on this branch before TASK-2521.03 and
   moves legacy `refined`/`active` records through `refine`/`activate`. Legacy
   files carry no recorded contract, so `refine` now refuses them. Import only
   records the lifecycle can hold without inventing a contract: `backlog`
   records become backlog Missions. Report every other legacy lane without
   importing it, naming why. Legacy files will be removed from the current tree
   (TASK-2521.07), so pin each imported Mission's trace to the source path *and*
   the commit it was read at. The task text is then recoverable from Git
   history without being copied into the database.
2. **Give Mission dependencies a home.** TASK-2521.03 dropped `dependencies`
   from the Mission and nothing replaced them. Record them as
   Mission-to-Mission references on the Mission aggregate, with typed
   version-checked `px` add/remove operations, reported by `px status` and
   `px status --json`. The importer maps the legacy `dependencies` key onto
   them. Nothing enforces dependencies today (agents and humans only read
   them), and this mission keeps it that way.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `px import-legacy` is explicit, dry-runnable and idempotent, and never runs from a normal command or acts as a fallback reader.
- [ ] #2 Legacy `backlog` records import as backlog Missions through the existing intake path. Legacy `refined`, `active`, `review`, `integration` and `done` records that are not already materialized are reported, not imported. No contract is invented and no lifecycle rule is bypassed.
- [ ] #3 Each imported Mission's `ExternalTaskRef` names the source path and the commit it was read at, so the source text can be recovered with `git show` after the file is removed.
- [ ] #4 Duplicate, malformed or conflicting records never overwrite an existing Mission and are never merged by guesswork.
- [ ] #5 Mission dependencies are Mission-to-Mission references on the Mission aggregate, can be added and removed through typed version-checked `px` operations, and are reported by `px status` and `px status --json`.
- [ ] #6 The importer maps `dependencies` frontmatter onto Mission dependencies and reports references that do not resolve to a Mission instead of dropping them.
- [ ] #7 No lifecycle, activation or scheduling rule consumes dependencies.
- [ ] #8 No task table, task port, task provider setting, task CLI or task status enum is introduced.
<!-- AC:END -->
