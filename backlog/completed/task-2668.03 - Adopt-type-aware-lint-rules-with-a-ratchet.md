## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`eslint.config.mjs` enables only syntactic rules (no-undef, no-unused-vars, eqeqeq, curly, no-var, and similar). For a product whose pitch is not trusting unchecked agent output, the repository's own static analysis is thin: nothing flags explicit `any`, unhandled or floating promises, unsafe assignments from `any`, or runaway function complexity. Agent-written code drifts toward exactly these patterns.

The outcome is type-aware linting (typescript-eslint's type-checked rule set or equivalent) running in `./scripts/verify-local.sh static-analysis` and CI, with a ratchet so existing violations cannot grow while they are paid down. Floating promises and new explicit `any` must be blocked immediately on changed code.

Depends on the two type-restoration subtasks so the rule set is not introduced against files that bypass the type checker.
<!-- SECTION:DESCRIPTION:END -->
