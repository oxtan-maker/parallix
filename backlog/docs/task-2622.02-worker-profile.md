# TASK-2622.02 worker dependency and setup profile

Measured 2026-10-01 on Node v24.21.0 with tsx 4.20.6. The reproducible raw
result is [task-2622.02-worker-profile.json](task-2622.02-worker-profile.json),
generated by `PARALLIX_PROFILE_SAMPLES=5 npx tsx scripts/profile-test-worker-cost.ts`.
Each value below is the median of five fresh process-isolated workers on the
same runtime. The loader in `scripts/test-worker-dependency-loader.mjs` observes
ESM resolve/load events; it never supplies modules or participates in selection.

## Dependency account and hotspot ranking

The loader recorded exact loaded URLs for every probe in the JSON artifact.
Its six bootstrap "unresolved" entries are tsx's extension-fallback attempts
for the existing `track-worker-temp-dirs.mjs`, not failed application imports;
the `.mjs` URL is subsequently loaded. Module-mock re-linking adds five such
fallback entries while reloading. These observations make unresolved attempts
visible rather than silently treating a static closure as complete.

Aggregate CPU is intentionally not extrapolated from a static graph: multiply
the measured per-worker increments only after the owning task identifies the
actual worker population. This report is diagnostic evidence, **not** a cache
key or a second test-selection authority.

### Identified repeat population

The current tier authority reported 406 unit, 209 integration-ci, and 9
integration-local files when profiled. A direct source-reference search found
18 test files mentioning `application-services.js`; these are the candidate
population, not proof that every worker evaluates the import. If each one
executes the broad import once in an isolated worker, the measured 838.3 ms
increment is a 15,089.4 ms aggregate wall-cost upper bound per complete pass.
The affected paths are the 18 paths printed by
`rg -l 'application-services\\.js' test --glob '*.test.ts'`; .04 must confirm
actual imports and worker counts before claiming a saving.

The common bootstrap imports `launcher-selection` for every ordinary worker;
its 42 evaluated local modules and 217.3 ms paired increment therefore have a
much broader potential population. The direct probe cannot establish a safe
aggregate figure while tests may use a different bootstrap or share fast-unit
execution. No evidence requires an architectural exception: both candidates
can be investigated behind existing typed ports and composition authority.

## Decision and escalation

No architectural boundary change is supported or proposed. The measured
opportunities fit existing ports-and-adapters constraints: narrow test-side
builders in .04, a parity-gated compile evaluation in .03, and only a bounded
launcher/composition edge investigation in .05. If .05 shows that a material
speedup requires changing composition authority, dependency direction, or an
architecture guard, that dependent change must stop for an explicit user
decision.
