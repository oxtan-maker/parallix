## Fixture adjustments that keep the same assertions

- Module-mock declarations of every section are hoisted into one `installModuleMocks()` call. The
  declaration order is a topological merge of the source orders because `installModuleMocks` relinks
  modules in declaration order.
- In suites with module mocks, production modules that a source imported statically are loaded with
  `await import()` after `installModuleMocks()`, so no module binds to an unmocked dependency before
  the facades exist. Types stay static `import type`.
- `task-2520` integration rebase state loads `integrate/rebase.js` with `importFresh`, because a sibling
  section already loaded it before the `rebase-workflow` facade existed.
- `git.test.ts` gained a section-level `mock.restoreAll()` so its last `node:child_process` module mock
  does not leak into the next section.
- Sources that carried a file-level `@ts-nocheck` (TASK-2328 debt) were grouped so that the nocheck marker
  stays file-level on suites made only of such sources; typed sources are type-checked.
