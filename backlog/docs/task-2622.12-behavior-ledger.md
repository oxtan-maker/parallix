# TASK-2622.12 — Behavior ledger (migration plan)

Migration plan for the recovery / supervision / current-work slice. Maps each
assigned legacy test identity to a destination behavior-owned suite (or a
justified equivalent), resolves cross-owner cases before any deletion, and
retains historical task IDs as regression provenance inside stable suites.

This is a planning artifact for TASK-2622.12, not a second selection authority.
Membership still comes from `test/lib/test-categories.ts`,
`test/lib/test-tier-selection.ts`, and `test/lib/test-run-plan.ts`. Same-line
coverage is never treated as proof that two behavioral assertions are equivalent
(AC#3 / TASK-2622.01 ledger policy).

## Migration status (complete)

All 31 assigned identities are migrated; every task-named source other than the
two already behavior-named suites (`mission-activity`, `recover-command`) is
renamed or merged and the originals deleted. Tier is preserved (26 unit, 5

## Routing rules

1. Mixed / task-named suites route to the owning contract, not to a filename
   guess. Every assertion keeps its original case name; the merged suite wraps
   each legacy file's cases in a `describe` block named for the guarantee and
   the historical task ID, so task IDs stay in the reported case path (AC#7).
2. Distinct input / error / order / state variants are retained. No scenario is
   deleted in this slice: every destination case count equals the source count
   (31 sources, 5 integration-ci + 26 unit, counts reported at verification).
3. Tier is preserved: a source in `INTEGRATION_CI_TESTS` lands in an
   integration-ci suite; a unit source lands in a unit suite. No default-tier,
   E2E, or local-only change.
4. Cases with module mocks (`mockModule`/`installModuleMocks`) stay in a file
   whose mocked module set is identical, because the mocks are file-wide.
5. No giant files: `src/`+`web/` <= 500 lines, tests <= 1000.
